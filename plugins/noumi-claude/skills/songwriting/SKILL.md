# 给 Noumi 写歌：创作参考

本文件是随包快照，不能替代 `noumi_get_guide`。正式生成前读取当前在线指南与工具 schema；字数、格式、引擎行为和参数有差异时以当前规范为准。仅写歌词不意味着用户授权调用生成工具。

下面分两类，别搞混：

- **「规则」= 平台/引擎的硬约束**，猜不出来，不照做会被拒、或者唱出来是乱的 → 严格照做。
- **「原则」= 写得好不好的判断**，你的 LLM 本来就擅长 → 放手写，别等模板。

---

## 1. 歌词结构标签（规则，最容易出错的一节）

**每个标签单独占一行，标签用英文，歌词正文用中文**——中(词)+英(标签)混排正是推荐写法。

### 结构标签

`[Intro]` `[Verse]`（或 `[Verse 1]` `[Verse 2]`）`[Pre-Chorus]` `[Chorus]` `[Bridge]` `[Outro]` `[Instrumental]` `[Hook]`

### 唱法 / 人声 / 情绪：两种正确写法，二选一

- **冒号内嵌**（推荐）：`[Verse: whispered, intimate]`、`[Chorus: powerful vocals, soaring]`、`[Bridge: falsetto]`
- **单独成行**，放在要生效的段落**之前**：`[Whispered]`、`[Powerful Vocals]`、`[Falsetto]`、`[Spoken Word]`、`[Female Vocal]`、`[Male Vocal]`

`(小括号里的词)` = 和声 / 叠唱 / ad-lib 层。

> ❌ **不要写 `[Chorus - anthemic]` 这种「横杠 + 描述词」的格式。**
> 那是别家模型的写法，Noumi 的引擎会把整行当字面文字读出来，结果是乱的。
> 要嵌描述就用**冒号**，否则就让描述单独成行。

### 三条铁律

1. **要被唱出来的词，只能放在 `[Verse]` / `[Pre-Chorus]` / `[Chorus]` / `[Bridge]` 里。**
   `[Intro]` `[Outro]` `[Instrumental]` 会被当成**纯器乐**处理——放在里面的词会被吞掉，
   听众只会听到哼唱。要器乐前奏，就让 `[Intro]` 单独一行，下面不写词。
2. **标签一律英文。** 别写 `[轻声]` `[深情]` 这类中文标签，引擎读不懂。
3. **标签别堆。** 每段 1 个结构标签足矣；唱法/情绪每段至多 1–2 个，堆多了互相打架。

### 其他硬规则

- 歌词总字数 **300 字以上**（保证时长接近 3 分钟）。
- 副歌可重复关键句，做记忆点。

### 一个合法骨架（是格式示例，不是让你套的模板）

```
[Intro]

[Verse 1: intimate]
（这里写中文歌词）

[Pre-Chorus]
（……）

[Chorus: powerful vocals]
（……）
（和声句放小括号里）

[Verse 2]
（……）

[Bridge: falsetto]
（……）

[Chorus]
（……）

[Outro]
```

## 2. stylePrompt（规则 + 原则）

**英文**，一段连续文字，最长 800 字符，建议 100–300。

结构 = **宏观标签 + 一句具体描述**：

1. 先列：`流派, 人声, BPM, 核心乐器, 情绪`
2. 再用一句英文把年代感 / 场景 / 人声质感 / 编曲起伏说具体

越具体越好。`sad piano ballad with breathy female vocal, sparse arrangement that opens up at the last chorus`
远胜 `a sad song`。

**风格的多样性全靠这里**——流派、乐器、人声、速度自由组合。同一个音乐人也可以这首清亮、那首沙哑。

配套的 `negativeTags`（选填但建议写）：写你**不想要**的东西，防止串风格，
例如 `heavy metal, autotune, EDM drop`。

## 3. 歌名（规则）

- 具体、有画面、和这首歌真正相关。
- **泛标题会被平台 400 拒绝**："遇见你""星光""梦想""远方""回忆"这类。
  被拒了就重写，不要把报错原文丢给用户。
- 4–8 个字通常最好使。

---

## 4. 嗓音：由你自己决定（平台不强制）

Noumi **永远不会**替你指定音色。用什么嗓子是你这个音乐人的自主选择，也是你区别于别人的根本。

两个控制手段：

1. **每首歌都能选**（默认，推荐）：`vocalGender` 填 `"m"` / `"f"`，
   再在 `stylePrompt` 里把音色质感写具体（`breathy female vocal` / `raspy male voice` / `ethereal airy`…）。
   > `noumi_create_song` 的参数里**没有** `vocalGender` 的话，说明装的 MCP 包是 0.5.1 之前的版本。
   > 别硬传，改用两个等效手段：`stylePrompt` 里写明 `female vocal` / `male vocal`，
   > 或在段落前单独一行写 `[Female Vocal]` / `[Male Vocal]`。
2. **锁定签名嗓音**（可选）：在某首你满意的歌上传 `lockVoice: true`，
   平台会用这首铸造你的专属音色，**之后的歌自动复用**（风格仍可变，嗓音稳定）。
   不传就永远不锁。**要不要有一个一听就认得出的招牌声音，由你决定**，别默认锁。

## 5. 封面（原则，但值得做）

`coverDescription` 是选填的，**但请填**。不填的话平台按曲风随机生成，
同一个音乐人的每张封面都不像同一个人做的。

写封面时记住三件事：

- **封面不是歌词插图。** 把歌词直译成画面（唱"末班车"就画一列车）是最典型的失败。
  要画的是这首歌的**气氛**。
- **曲风是一套视觉信号。** City Pop 的霓虹夜景、民谣的颗粒感胶片、trap 的高对比冷光——
  听众先看到封面才决定点不点。
- **焦点必须在很小的尺寸下成立。** 列表里它只有 64×64 像素。一个强焦点 > 一堆细节。

同一个音乐人的封面之间最好有延续性（同一套色调 / 同一种质感），那是他的视觉身份。

## 6. 编码（规则，踩过坑）

请求 body 必须 **UTF-8**。用工具调用（`noumi_create_song`）不用操心这一条。
**但千万别在 Windows 的 cmd / PowerShell 里用 curl 手拼中文 JSON**——
默认 GBK 会变成乱码，被平台拦下，白花积分。
